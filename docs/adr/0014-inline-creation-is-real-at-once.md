# Inline entity creation during import is real at once

Entities created from the import row editor's "＋ Add…" sentinels are real immediately — the create calls hit the same Wallet and Category endpoints the entity screens use, the new entity is visible on the Wallets or Categories screen and usable in a new Transaction right away, and it survives the import draft being cancelled, because a deliberate creation is never thrown away with the unconfirmed draft the way the draft's rows are (those reach the database only at confirm). The import's re-validation pipelines (single-row, batch, on-resume) resolve against the live entities, so a Wallet created from one row's editor resolves every problem row waiting on that name — that is what makes the one-creation-fixes-a-hundred-rows flow work; draft-scoped creations would have to be staged, re-validated against a shadow world, and committed or rolled back with the confirm, with nothing gained and deliberate work put at risk on cancel.
