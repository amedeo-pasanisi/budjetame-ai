# Excel Export mirrors the Import template

The app gained an Excel export (US 7.3) after "Data export" was dropped from the non-goals. The export writes the Account's filtered Transactions as a .xlsx in the exact import template format — same columns, same positive-amount convention, one flat sheet — so one format, one parser, one documented contract serves both directions. It is deliberately lossy in three places: Opening Balance Transactions are not exported (the template's type vocabulary is expense | income | transfer only; extending it so imports could create Opening Balances was considered and rejected because Opening Balance Transactions are created only by the Wallet lifecycle and are read-only); Recurring links are not carried (imports never set links, so a round-trip cannot restore them); and Places flatten to coordinates. Round-trip re-import into a fresh Account — Wallets and Categories created first — restores the ledger without Duplicates. A future reader should not "fix" the export by adding columns or re-including Opening Balances without reopening this decision.
