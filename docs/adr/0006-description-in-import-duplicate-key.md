# The import duplicate key includes the description

US 7.1 defines the import duplicate key as date + amount + wallet + category for expense/income rows and date + amount + source + destination for transfers; the code already deviates by including the Type in the expense/income key. The key now also includes the description for every row type, so two rows are Duplicates only when date, amount, type, wallet(s), category, *and* description all match (a blank description matches a missing one). Decided because the user wanted rows distinguishable only by their description (e.g. two same-day, same-amount payments to the same place) to import, and because Verification can now fix a duplicate by changing the description alone. The trade-off is recorded deliberately: the same real-world transaction imported twice with slightly different descriptions is no longer flagged — a future reader should not "fix" the key back to the spec's shorter form.
